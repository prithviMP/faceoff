# Security and privacy

This is a local educational workbench, not an authenticated multi-user service. Bind to localhost, as the CLI does. Do not expose it publicly with private datasets.

Imported text and handbook descriptions are untrusted evidence. Prompts tell providers not to follow instructions in evidence, but prompt-injection resistance is not guaranteed. Enabling a remote provider transmits selected passages and navigation descriptions. Use data you are authorized to process.

Archive imports reject traversal and symlinks and limit expanded size/file count. Folder imports should contain only intended source files. Do not import folders with secret-bearing symlink targets. PDF extraction is not a sandbox and does not perform OCR. SQLite execution uses read-only connections with result/time bounds; review imported recipes, database locations and business definitions before recording human review.

Local review labels and receipt databases are not cryptographic signatures. Anyone who controls the project files can alter them. Receipts establish local execution consistency, not trust against a hostile host. There is no arbitrary shell executor.

For vulnerabilities, use the repository's private vulnerability reporting feature if enabled, or contact a maintainer privately through a profile-listed channel. Avoid including keys, private datasets or exploit details in public issues. No hosted security-reporting service or response SLA is configured by this project.
